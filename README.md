# 📚 读书笔记管理系统

一个**零依赖、纯本地**的读书笔记工具：读到什么就粘什么，系统自动帮你拆条、抽标签、按时间和主题归档；需要的时候再把同一主题的零散笔记归拢起来，分析、组织，生成一篇成型的读书笔记。

> 📖 **只想使用的话看 [使用说明.md](使用说明.md)** —— 安装、操作、备份、常见问题都在那里；本文档偏项目结构与实现说明。

- 前端：原生 HTML/CSS/ES Module，没有构建步骤，没有打包器
- 后端：Node.js 自带 `node:sqlite`，**不需要 `npm install`**，项目里没有 `node_modules`
- 数据：全部存在本机 `data/notes.db` 里，默认不联网（除非你自己开 AI 综述）

## 快速开始

需要 Node.js ≥ 22.5（用到内置的 `node:sqlite`）。本机实测 v24 正常。

**Windows：双击项目根目录的 `启动读书笔记.bat`** —— 自动启动服务并打开浏览器，重复双击也不会起两个服务。

命令行方式（各平台通用）：

```bash
node --no-warnings src/index.js      # 或者 npm start
npm run open                         # 启动并自动打开浏览器（等同双击启动文件）
```

然后打开 <http://127.0.0.1:7788>。

想先看看装满数据长什么样：

```bash
npm run seed        # 写入 25 条示例笔记（数据库非空时会自动跳过）
```

配置项（都有默认值，一般不用管）：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `7788` | 端口 |
| `HOST` | `127.0.0.1` | 监听地址。改成 `0.0.0.0` 才能被局域网其它设备访问 |
| `NOTES_DB` | `data/notes.db` | 数据库文件路径 |
| `QUIET` | — | 设为 `1` 不打印每条请求日志 |
| `DEEPSEEK_API_KEY` 等 | — | 见下面「AI 综述」 |

## 一、粘贴即存

**在页面任何位置按 `Ctrl+V`**，就会自动跳到记录台并把剪贴板内容解析好；也可以直接把 `.md` / `.txt` 文件拖进去。

**截图和文字可以一起粘、一起存。** 三种进图方式：

| 怎么进 | 说明 |
| --- | --- |
| `Ctrl+V` 直接粘贴截图 | 在记录台输入框里粘贴，图片插在光标处，旁边的文字照常落地；在页面别处粘贴也行，会自动跳到记录台 |
| 拖进来 | 把图片文件拖到输入框上（和 `.md` / `.txt` 可以一起拖） |
| 🖼 图片 按钮 | 点工具栏的「🖼 图片」选一张或多张（可多选） |

图片会以 Markdown 的形式插在文字中间：`![](/api/attachments/xxxxxxxx)`。保存时它和文字是同一条笔记，卡片、预览、搜索、导出全都按这个来。

一些实际会遇到的细节：

- **大截图会自动缩小**：超过 2.5MB 的图在浏览器里等比缩到长边 2200px 以内再上传（PNG 仍是 PNG，不动 GIF 动画），缩过会在右下角告诉你「原图多少 MB」
- **单张上限 12MB**，只收 PNG / JPEG / GIF / WebP / BMP；别的类型会被直接拒绝并给出提示
- **点卡片里的图片能放大看**，按 `Esc` 关掉
- **没保存就关页面**：粘进来但没保存的图片算「没人引用」，会在 7 天后被自动清掉（设置页有「清理没用的图片」按钮可以立即清）；**正在被你笔记引用的图片永远不动**
- 图片直接存在 `data/notes.db` 里，所以「备份＝复制这一个文件」这句话依然成立

解析器认得这些写法（**顺序无所谓，认得出来就抽走**）：

```
《反脆弱》 P167                       → 主题 + 页码
《反脆弱》 第 3 章                     → 主题 + 章节
主题：不确定性                         → 主题（推荐写法，自由文本）
作者：塔勒布       译者：雨珂          → 作者 / 译者
类型：摘录                             → 笔记类型
类型：金句                             → 自己造的类型也照收
日期：2026-02-11   2026年2月11日       → 笔记日期
#决策 #复利                            → 标签（正文里出现的也会抽出来）
```

**主题和类型都是自由文本，没有枚举限制。** `《书名》` 会自动填进主题，但你显式写的 `主题：xxx` 优先级更高。类型用内置的 `摘录/想法/疑问/小结/待办` 时中文英文都认；写别的词（如 `类型：金句`）就原样当自定义类型存下来，卡片角标、时间轴的「按类型回看」、`类型:金句` 搜索都会跟着用。空白字符会被去掉，最长 16 字，留空则默认「想法」。

正文首行写 `摘录：……` / `想法：……` / `疑问：……` 也能直接定类型。Markdown 的 `# 标题` 会被当成标题，而 `#标签`（`#` 后面没有空格）不会被误认为是标题。

几种常见用法：

- **一次贴多条**：中间用单独一行的 `---`（或 `***`、`===`）隔开，会被拆成多条笔记
- **整段就是一条**：工具栏的解析模式选「整段作为一条」
- **保存前改**：预览卡片上每一项都可以直接改（标题、主题、位置、日期、类型、作者、标签），主题和类型都是普通输入框，随便填，确认无误再按 `Ctrl+Enter` 一次全部保存
- **判重**：内容与主题都相同的笔记会被自动识别，避免重复粘贴时写重

## 二、按时间和主题打标签

标签分三类，用起来不需要你操心：

| 类型 | 例子 | 怎么来的 |
| --- | --- | --- |
| **时间标签** | `#2026年` `#2026-02` `#2026-W07` | 由笔记日期自动生成，改日期会自动跟着变，不可手动删 |
| **主题标签** | `#决策` `#沉没成本` | 从你写的 `#标签` 里来（可在设置里关掉自动提取） |
| **自定义标签** | 随便什么 | 在笔记上手动加 |

自动加的标签如果不对，直接点标签上的 `×` 去掉即可；系统会记住「这条笔记不要这个标签」，下次不会再给你加回来。左侧栏的「时间」「主题」两个分区可以按年/月/周、按主题来回看。

> 「标签」和「主题」是两件事：标签是 `#决策` 这种一条可以有好几个的；主题是每条笔记上那个自由填写的单个字段。

## 三、查阅

顶部搜索框支持语法，可以混着用：

| 写法 | 含义 |
| --- | --- |
| `认知失调` | 全文搜索（标题 + 正文 + 主题） |
| `#决策` | 按标签过滤，多个标签可叠加 |
| `@反脆弱` 或 `主题:反脆弱` | 按主题过滤（`来源:` 老写法仍兼容） |
| `类型:摘录` / `kind:idea` | 按笔记类型过滤（内置的摘录 / 想法 / 疑问 / 小结 / 待办，**自定义类型直接写原词**） |
| `after:2026-01-01`、`before:2026-03-01` | 按日期区间 |
| `date:2026-02` | 整个月 |
| `星标` / `is:starred` | 只看星标 |
| `"原样短语"` | 精确短语匹配 |

左侧栏还提供快捷视图（全部 / 星标 / 今天 / 最近 7 天 / 最近 30 天）、按标签、按时间、按主题的分面统计，点一下就是一次过滤；笔记卡片支持多选，选中后可以直接「拿去分析」。

其它视图：

- **时间轴**：按月梳理阅读轨迹，看每个月的产出与主题分布
- **标签管理**：重命名、合并（同名重命名会自动合并）、清理没用的标签

## 四、组织与分析，生成读书笔记

「主题分析」视图把零散笔记归拢成一篇结构化的读书笔记：

1. **选范围** —— 勾几条笔记，或选一个/多个标签、一个主题（多标签还可以选「满足任一」或「同时满足」）
2. **生成** —— 先出一份分析：主题概览、关键词脉络、核心摘录、按主题整理、想法与小结、疑问与待深入、关联主题
3. **落笔** —— 生成 Markdown 格式的读书笔记，可以复制走，也可以勾选「生成后存回系统」（以「小结」类型入库，形成闭环）

关键词是从中文里用 2/3-gram 统计出来的，不需要分词器，专有名词和术语基本都能浮出来。**没有 API Key 也能完整使用**——这一步完全由本地分析引擎完成。

### AI 综述（可选）

配置一个 OpenAI 风格的接口（DeepSeek、OpenAI、本地 Ollama 都行）后，生成的读书笔记开头会多一段 AI 写的综述。在「设置 → AI 综述」里填 Base URL / 模型 / API Key，点「测试连通性」可以直接验证。

也可以走环境变量：`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`（环境变量优先于设置页里的值）。

> API Key 保存在本机数据库里，只会用于请求你自己配置的那个接口地址，不会发往别处。系统提示词明确要求模型不得编造材料里没有的内容。

## 五、数据、备份与恢复

数据都在一个 SQLite 文件里（默认 `data/notes.db`）。三种备份方式，按稳妥程度排序：

1. **导出 JSON 备份**（设置页，或直接访问 `/api/export/json`）——最稳妥，服务运行中也能用
2. **导出 Markdown / CSV**（`/api/export/markdown`、`/api/export/csv`）——适合放到别的笔记软件里
3. **复制 `data/notes.db`**——请先停掉服务再复制

**图片也在这个文件里**（以 BLOB 形式存在 `attachments` 表），所以上面三种备份都天然包含图片：

- JSON 备份里的图片是 base64，导入时会一起还原，正文里的引用还是指向同一张图
- Markdown 导出会把每张图按 base64 内嵌成 `data:image/...`，所以导出的 `.md` 换台机器、断网打开也照样看得到图；文件开头会注明「内含 N 张图片」

恢复：设置页「导入 JSON 备份」，采用跳过重复策略，同样内容不会写两遍。

设置页的「清理没用的图片」只删**没有任何笔记引用**的图片（例如粘进记录台又没保存的），正在用的图片绝不会动。服务每次启动也会自动做一次同样的清理（只清 7 天前就没被引用过的）。

**清空全部数据**：停掉服务，删掉 `data/notes.db`（如果存在，把 `notes.db-wal`、`notes.db-shm` 一起删掉），重新启动即可。想重新灌示例数据就再跑一次 `npm run seed`（数据库非空时用 `FORCE=1` 可以强制覆盖）。

## 六、自检

```bash
npm test            # 72 项：工具函数、解析、入库、检索、标签、分析、图片附件、导入导出、前端 Markdown 渲染、旧库字段迁移
npm run test:e2e    # 90 项：起一个独立实例，把 HTTP 接口全流程走一遍
npm run test:ui     # 78 项：用本机 Chrome/Edge 无头渲染每个视图，检查是否卡住、抛错、点不动（加 SHRINK=1 是 87 项）
```

`test:e2e` 会自己起一个临时实例（端口 7799、独立数据库）并在结束后清理。`test:ui` 需要本机装有 Chrome 或 Edge，没装会自动跳过；它也可以指向别的地址：

```bash
# macOS / Linux
BASE=http://127.0.0.1:9000 npm run test:ui

# Windows PowerShell
$env:BASE="http://127.0.0.1:9000"; npm run test:ui
```

`test:ui` 的探针会真的模拟一次「粘贴截图」并在验完后把那张图删掉，所以在你的正式库上跑也不会留下垃圾。但如果你想让「卡片上的图片能显示」「主题分析有概览」这类检查也真的跑起来，可以指向一个**临时库**并加上 `SEED_IMAGE=1`（它会先插 3 条普通笔记 + 1 条带图的，只该用在临时库上）：

```bash
# Windows PowerShell
$env:PORT="7789"; $env:NOTES_DB="data/ui-check.db"; node --no-warnings src/index.js   # 另开一个窗口
$env:BASE="http://127.0.0.1:7789"; $env:SEED_IMAGE="1"; npm run test:ui
```

再加上 `SHRINK=1` 会多跑 9 项**大截图压缩**检查（造一张 3000×2000 的图，验证它被等比缩到长边 2200 以内、体积变小、能正常存取），同样只该用在临时库上：

```powershell
$env:BASE="http://127.0.0.1:7789"; $env:SEED_IMAGE="1"; $env:SHRINK="1"; npm run test:ui
```

## 八、实现上的几点说明

- **为什么不用 FTS5**：中文没有分词，FTS5 的默认分词器对 CJK 基本不可用；这里用 `LIKE` 子串匹配 + 关键词抽取，检索行为可预期，也不需要额外依赖。
- **为什么零依赖**：这个工具的价值在于你的笔记要能放十年。没有依赖就没有升级、没有供应链、没有 `npm audit`，只要有 Node 就能跑起来。
- **时间标签不可删**：它们是笔记日期的一个视图，删掉只会造成不一致，所以直接禁用了。
- **前端出错会报出来**：页面顶部有一个脚本错误横幅，前端一旦抛异常会直接显示，而不是留下一个「半死」的页面。
- **「主题」原来是「来源」**：字段曾叫 `source`，现在统一叫 `topic` 且完全自由填写。启动时会自动迁移旧库（`ALTER TABLE notes RENAME COLUMN source TO topic`），老数据一条不丢；导入旧版 JSON 备份时 `source` 字段也照样认。`来源：xxx` 这个粘贴写法作为别名保留了下来，但界面里已经不再出现「来源」二字。
- **为什么不做「任意 `Xxx：` 就是自定义类型」的推断**：「注意：」「正文：」「小结：」这类行太常见，猜错了比不猜更烦人。自定义类型要么显式写 `类型：金句`，要么在预览卡片/编辑弹窗里直接填 —— 那两个框就是普通文本框。
- **显式写的压过猜出来的**：`《书名》` 会被自动填进主题，但你另写的 `主题：xxx` 一定赢；同理 `类型：金句` 能盖过从 `摘录：…` 推测出来的类型。同名字段仍然「第一个显式值胜出」。
- **图片为什么存进数据库，而不是放个 `uploads/` 目录**：这个项目的承诺是「备份＝复制 `data/notes.db`」。图片一旦散落在文件系统里，这条承诺就废了：备份要记得带上目录，删库会留下垃圾文件，导出/导入也会断掉引用。存 BLOB 的代价是数据库文件变大、每次读取都过一次 SQLite，对个人笔记这个量级完全够用。
- **图片上传为什么用 base64 JSON**：不想为了几张图手写一个 multipart 解析器（那是几百行容易出错的代码，还得处理边界、编码、临时文件）。代价是传输量多三成，所以图片本身限制 12MB、请求体限制 24MB —— 有明确的天花板，比一个可能有边界 bug 的解析器可靠。
- **图片为什么会「自己消失」**：正文里的引用是唯一的真相来源。图片只在「没有任何笔记的正文里提到它」且「超过 7 天」时才会被清理 —— 用 `note_id` 判断是不够的，同一条笔记可能被保存两次、也可能共享同一张图，所以清理前会真的去扫一遍正文。
- **图片行不会打断元信息识别**：`摘录：…` / `![](...)` / `日期：…` 这种粘贴里，图片行现在仍然算「还在元信息区」，所以末尾的 `日期：` 还是会被抽成笔记日期，而不是留在正文里多出一行。
- **单行图片不会被当成标题**：`![](…)` 这种行会被标题推导跳过，否则只贴一张图就会被推出一串乱码当标题。
